Problem Formulation & The "Illusion of Forgetting"

[content]
- Legal Foundation: GDPR Article 17 ("Right to be Forgotten") & CCPA compliance.
- The Core Technical Dilemma:
  * Retraining from Scratch (M_retrain): Perfectly private (epsilon = 0 leakage), but scales 
    as O(T * K) communication rounds; completely unscalable in production.
  * Naive Output-Masking / Zeroing: Manually setting classifier weights or biases to negative 
    constants (e.g. bias = -50.0).
- The "Illusion of Forgetting":
  * Output masking changes only top-level class recall to 0%.
  * Deep convolutional filters (layer1 through layer4) remain 100% trained on the forgotten data.
  * Adversaries executing Membership Inference Attacks (MIA) easily detect residual feature 
    activations and extract private training fingerprints.
- Research Objective:
  * Develop a principled, rapid unlearning pipeline that surgically removes private feature 
    influence, preserves retained client utility (>90% accuracy), and is verifiable via visual 
    attribution metrics.

[how to present]
- Pacing: 50 seconds.
- Spoken Script:
  "The fundamental challenge in machine unlearning is avoiding what we term the 'Illusion of 
  Forgetting.' A trivial approach would simply be zeroing out or heavily penalizing the output 
  classifier weights for the requested class. While that superficially brings class recall to zero, 
  the deep convolutional filters remain completely conditioned on the forgotten data. This creates 
  a false sense of privacy: any adversary with shadow models can extract latent features. What we 
  need is true parameter and representation remediation—erasing the forgotten client's influence 
  from deep latent representations while guaranteeing zero collateral damage to the remaining clients."

[pausible questions that can be asked]
- Q1: "How do you distinguish between legitimate unlearning and intentional catastrophic forgetting?"
  * Winning Answer: "We evaluate two coupled criteria: Unlearning Fidelity on the forgotten data 
    (measured by prediction agreement with an exact retrained model and cross-entropy loss shifts), 
    and Retained Task Utility (ensuring test accuracy on retained clients suffers virtually zero drop, 
    maintaining >91% accuracy)."
- Q2: "What is the threat model here? Black-box or White-box?"
  * Winning Answer: "We address both: black-box auditing via output confidence and prediction agreement, 
    and white-box auditing by inspecting internal feature maps at layer4 using Grad-CAM."

[topic]
Backbone Architecture & Non-IID Representation Engineering

[content]
- Vision Backbone: ResNet-18 initialized with ImageNet-pretrained weights.
- Three Architectural Solutions to Prevent Extreme Non-IID Representation Collapse:
  1. Frozen BatchNorm Running Statistics (freeze_bn):
     - Problem: In Non-IID or single-class client training, computing local batch mean and variance 
       corrupts running statistics and destroys pretrained normalization.
     - Solution: BatchNorm running_mean and running_var are permanently frozen in evaluation mode; 
       feature scaling remains rock-solid across skewed batches.
  2. Scaled Cosine-Normalized Classifier Head:
     - Logits computed on the unit hypersphere:
         logits(x) = scale * ( phi(x) / ||phi(x)|| ) * ( W^T / ||W|| )   [scale = 20.0]
     - Bounds logit magnitudes, eliminates gradient explosion from unbalanced classes, and enforces 
       angular separation.
  3. Class Prototype Centroid Initialization:
     - Round 0 initializes class prototype vectors to empirical normalized feature centroids:
         W_c = normalize( E_{x in D_c}[phi(x)] )
     - Provides robust zero-shot geometric separation prior to federated optimization.
- Optimization Protocol: Local SGD on base.layer4 (residual block 4) and classifier head 
  (lr=0.003, momentum=0.9, weight_decay=1e-4).

[how to present]
- Pacing: 60 seconds.
- Spoken Script:
  "When training vision models under extreme Non-IID partitioning—such as 1-client-1-class—standard 
  ResNets suffer severe representation collapse. Why? Because local BatchNorm layers update their 
  running statistics on single-class batches, completely destroying feature stability. To solve this, 
  we implemented three crucial architectural innovations: First, we permanently froze BatchNorm 
  statistics in evaluation mode. Second, we replaced standard unbounded linear inner products with a 
  scaled cosine-normalized classifier on the hypersphere with scale factor 20. Third, we initialized 
  all class weights directly to empirical feature centroids. This stabilizes local optimization so 
  clients train only the final convolutional block (layer4) and the head, preserving high feature 
  capacity."

[pausible questions that can be asked]
- Q1: "Why only train layer4 instead of the entire ResNet-18 network?"
  * Winning Answer: "In federated learning on edge devices, transmitting 11.2 million parameters per 
    round creates excessive communication overhead. Lower convolutional layers (layers 1-3) encode 
    generic low-level visual primitives (Gabor edges, color blobs, textures) which transfer well from 
    ImageNet. By localizing training to layer4 and the classifier head, we achieve over 93% accuracy 
    while cutting trainable communication parameters by over 25%."
- Q2: "What is the mathematical benefit of the cosine head over standard linear layers?"
  * Winning Answer: "Standard linear layers allow logit magnitudes to grow unboundedly based on weight 
    norms, which causes dominant clients to overpower minority clients. Cosine normalization maps 
    both features and class vectors to the unit sphere, ensuring that predictions depend strictly on 
    angular distance, preventing gradient domination under label skew."

[topic]
Explainable AI (XAI) Auditing: Grad-CAM Attribution Drift

[content]
- Explainability Objective: Provide visual, verifiable evidence that the model has stopped 
  relying on forgotten visual features.
- Visual Attribution Hook: Hooked into penultimate residual block output: self.base.layer4.
  * Spatial feature grid: 4x4 resolution interpolated to 128x128 input dimensions.
- Quantitative Spatial Attention Drift Metric (|Delta CAM|):
  * For any image x, let CAM_orig(x) and CAM_unlearn(x) be 2D attention heatmaps normalized to [0, 1].
  * Spatial Attribution Drift:
      Drift(CAM_1, CAM_2) = 1.0 - PearsonCorrelation( vec(CAM_1), vec(CAM_2) )
  * Interpretation:
      0.0 = Identical spatial focus (Zero visual change)
      1.0 = Completely orthogonal / dispersed visual attention
- Auditing Requirement:
  * Forgotten Data: High drift (|Delta CAM| >> 0), indicating feature suppression or redistribution.
  * Retained Data: Near-zero drift (|Delta CAM| < 0.05), proving retained visual attention is preserved.

[how to present]
- Pacing: 50 seconds.
- Spoken Script:
  "To prove to auditors and regulators that unlearning actually occurred, accuracy numbers alone are 
  insufficient. We built an Explainable AI pipeline using Gradient-weighted Class Activation Mapping 
  (Grad-CAM) hooked into the output of layer4. To quantify visual change, we formulated the Spatial 
  Attribution Drift metric, based on Pearson correlation distance. If unlearning is successful, the 
  attention heatmap on forgotten images must collapse or disperse into background context, yielding 
  high drift, while retained classes must exhibit near-zero drift, proving that the model's visual 
  perception of other objects remains untouched."

[pausible questions that can be asked]
- Q1: "Why did you hook Grad-CAM to layer4 rather than layer1 or layer2?"
  * Winning Answer: "Layer4 contains the deepest convolutional representations with the highest 
    semantic receptive fields. Lower layers only fire on generic edges and colors, which must not be 
    erased. Layer4 captures the actual object-level semantics where class identity is formed."
- Q2: "Why do Grad-CAM heatmaps on CIFAR-100 highlight textures or backgrounds rather than sharp silhouettes?"
  * Winning Answer: "This is a known property of CNN receptive fields on low-resolution 32x32 images. 
    Unlike humans who perceive sharp line-art contours, deep neural networks utilize contextual textures, 
    surface contrast, and contact shadows for classification. Grad-CAM measures what the network 
    empirically utilizes for its prediction."

[topic]
The Critical Bottlenecks of FedEraser

[content]
- FedEraser Mechanism: Maintains historical checkpoints W_0 .. W_T and client update vectors Delta W_{t, k}. 
  Reconstructs unlearned model via milestone calibration steps scaled by historical momentum.
- Three Fatal Scalability Bottlenecks of FedEraser:
  1. Massive Storage Footprint: O(T * K * |theta|)
     - Server must store global checkpoints and per-client update tensors across all rounds.
     - At T = 20 rounds and 10 clients, storage exceeds 7.2 GB on disk!
     - In enterprise FL with 100 rounds and 1,000 edge clients, storage demands reach TERABYTES.
  2. Active Retained Client Wake-Up:
     - At unlearning time, retained clients MUST be online to compute calibration passes.
     - If retained edge devices are offline, unlearning stalls.
  3. The Trajectory Drift Horizon:
     - Applying historical gradients to an unlearned model creates curvature mismatch:
         grad L(W_t) != grad L(W'_t)
     - Over very long horizons, accumulated curvature error causes divergence from M_retrain.
- The Urgent Research Need: Can we achieve zero-storage, server-only unlearning?

[how to present]
- Pacing: 55 seconds.
- Spoken Script:
  "While FedEraser works well algorithmically, as systems engineers we must confront its severe 
  practical bottlenecks. First: storage explosion. FedEraser stores the full trajectory of models 
  and client updates—scaling as O(T * K * |theta|). In our 20-round run, the cache file ballooned to 
  7.2 gigabytes. In cross-device FL with thousands of devices, storing trajectories is impossible. 
  Second: client wake-up. Retained clients must be online to execute calibration passes whenever an 
  unlearning request arrives. Third: trajectory drift over long horizons. This motivated our pursuit 
  of a novel unlearning paradigm: server-only, zero-history unlearning."

[pausible questions that can be asked]
- Q1: "Why can't the server just delete the historical cache after training?"
  * Winning Answer: "If the server deletes the historical cache, FedEraser cannot run at all—it has 
    no trajectory to calibrate against, forcing the system back to exact retraining from scratch."
- Q2: "How does trajectory drift manifest mathematically?"
  * Winning Answer: "Because historical update vectors were evaluated at weights containing the 
    forgotten client's influence, re-applying them to unlearned weights introduces a first-order Taylor 
    error that compounds across successive rounds."

[topic]
The Novel Method: Fed-CNS (Contrastive Null-Space Scrubbing via Additive Ledger)

[content]
- Breakthrough Objective: Eliminate round history storage and eliminate retained client wake-up.
- Component 1: The Additive Ledger (Linear Sufficient Statistics)
  * Feature Second-Moment Matrix: A_k = sum_{x in D_k} phi(x) phi(x)^T   [512 x 512, 1.05 MB]
  * Class Prototype Sums:         S_{k, c} = sum_{x in D_{k, c}} phi(x)  [10 x 512,  20 KB]
  * Exact Closed-Form Subtraction (GDPR Compliant):
      A_retained = A_all - A_forget  |  S_retained = S_all - S_forget
  * Storage: O(d^2 + C * d) = 1.02 MB total (Independent of rounds T and clients K!).
  * Retained Clients: 100% Offline (Zero wake-up calls).
- Component 2: Contrastive Generalized Eigenproblem
  * Solves: max_v (v^T Sigma_f v) / (v^T (Sigma_r + rho * I) v)  <=>  Sigma_f v = lambda Sigma_r v
  * Extracts private memorization eigenvectors V_private (subspace dimension k).
- Component 3: Null-Space Scrubbing & Prototype Re-centering
  * Builds Null-Space Projector: P_perp = I - V_private V_private^T
  * Re-centers prototypes: W_c = normalize( S_retained[c] / n_retained[c] )
  * Projects classifier head: W_unlearn = normalize( W_retained * P_perp )
- Benchmark Execution: Runs in 515 milliseconds (< 0.52s) on GPU!

[how to present]
- Pacing: 65 seconds.
- Spoken Script:
  "To overcome FedEraser's bottlenecks, we developed Fed-CNS: Contrastive Null-Space Unlearning 
  powered by an Additive Ledger. Here is the core insight: instead of saving gigabytes of round 
  weights, we track linear sufficient statistics: the feature second-moment matrix A (512x512) and 
  prototype sums S. At float32, this takes just 1.02 megabytes. Because sample sums are additive, when 
  a client leaves, the server simply subtracts their matrix: A_retained = A_all - A_forget. Retained 
  clients stay 100% offline! The server then solves a contrastive generalized eigenproblem to isolate 
  the private latent directions where the forgotten client concentrated its variance, and projects 
  the classifier head onto the null space of that private subspace. Total server execution takes just 
  515 milliseconds—a 60x speedup over retraining with a 2,000x storage reduction."

[pausible questions that can be asked]
- Q1: "How can 1.02 MB of data represent what previously required 2.2 GB of checkpoints?"
  * Winning Answer: "FedEraser stores redundant parameter trajectories over time. Fed-CNS recognizes 
    that the classifier head and feature distribution at convergence are governed by the first and 
    second moments of penultimate features (phi(x) in R^512). The covariance of a 512-dim embedding 
    is fully captured by a 512x512 matrix (1.05 MB), bypassing parameter trajectory caching."
- Q2: "Why do retained clients not need to wake up?"
  * Winning Answer: "Because sample moments are additive: sum(all) = sum(retained) + sum(forget). 
    The server derives the retained statistics strictly by subtracting the leaving client's summary, 
    eliminating any need to ping retained devices."

Rigorous Peer-Review Audit: Exposing the Limitations of Fed-CNS

[content]
- Scientific Integrity: A research partner must ruthlessly audit its own proposals.
- Critical Audit Findings & The "Loss Paradox":
  1. The Loss Paradox in Setting B:
     * While prediction agreement reached 96.9%, cross-entropy loss on D_forget dropped from 
       0.3034 to 0.2954!
     * The model actually fit the forgotten client slightly BETTER, because the baseline model 
       already agreed with retrained on 98.58% of samples!
  2. The Label-Skew Confound:
     * In Dirichlet non-IID partitioning, Client 09 holds 177 bottles and 84 beavers.
     * An uncentered covariance A_f = sum phi phi^T without class conditioning reflects class 
       imbalance (label skew), rather than private instance memorization.
  3. The Readout-Only Limitation:
     * Modifying only the classifier head leaves convolutional kernels in layer4 untouched.
     * While black-box logits are scrubbed, a white-box attacker inspecting internal activations 
       could still detect residual feature traces.
- The Architectural Solution (Class-Conditional 2-Tier Architecture):
  * Class-Conditional Ledger: Store A_{k, c} per class (10.2 MB), isolating instance variance.
  * Tier 2 Weight Null-Space: Project unlearning gradients on layer4 into Null(F_retain).

[how to present]
- Pacing: 65 seconds.
- Spoken Script:
  "True scientific progress requires ruthless peer-review of our own methods. When we audited Fed-CNS, 
  we discovered a critical subtlety: in Setting B, while prediction agreement reached 96.9%, the loss 
  on forgotten data dropped to 0.2954. Why? Because the baseline model already agreed with retrained 
  on 98.58% of samples! Furthermore, because Client 09 held mostly bottles and beavers, an unconditioned 
  second-moment matrix captured class label skew rather than private instance memorization. 
  Additionally, modifying only the classifier head leaves layer4 convolutional filters unscrubbed in a 
  strict white-box attack. To solve this, we formulated the Class-Conditional Ledger (storing A_{k,c}

    and isolates only the client-specific instance variance."
